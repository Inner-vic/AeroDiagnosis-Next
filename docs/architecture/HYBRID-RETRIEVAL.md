# 多路召回与 Top K 融合设计

## 目标

多路召回用于解决知识文档、知识图谱和案例库的评分口径不一致问题。它输出的是可审计的
证据排序，不把检索相关度解释为故障概率。

## `weighted_rrf@2`

系统对三条路由分别扩大候选集，并记录路由内排名 `r`、原始分 `s` 和路由权重 `w`：

| 路由 | 内容 | 权重 |
|---|---|---:|
| `manual` | 活动版本的知识文档片段 | 1.00 |
| `graph` | 活动版本的知识图谱节点或路径 | 0.88 |
| `case` | 已确认的版本化案例 | 0.94 |

生产策略的单路贡献采用以下确定性计算：

```text
normalized_rrf(r, k) = (k + 1) / (k + r)
route_score = w × normalized_rrf(r, k)
```

同一证据若被多路命中，融合分累加各路贡献并截断到 1。算法版本、`k`、路由权重与覆盖约束
都随结果保存；变更融合公式时必须产生新的算法版本。

离线实验还支持三种单路策略、无权 RRF、不同 `k` 的敏感性分析和归一化原始分融合。
这些策略与生产问答共用候选生成和排序代码，避免实验实现漂移。

## 来源覆盖约束

当 `Top K >= 3` 时，系统先从每条有结果的路由保留一个最高分候选，再按融合分补足剩余位置。
每条结果明确标记为：

- `route_coverage`：为了保证来源覆盖而入选；
- `fused_score`：按照融合分进入剩余名额。

该约束避免某一路由因为分数尺度、语料数量或重复内容占满结果。它提高的是证据来源多样性，
并不保证结果必然相关，因此仍需在人工标注集上评测。

## 可观测输出

`POST /api/retrieval/hybrid` 为每条证据返回：

- 原始来源与稳定 `evidence_id`；
- 路由内排名和原始分；
- 归一化分、RRF 分量和路由权重；
- 最终融合分与入选原因；
- 各路由的候选数量、入选数量和最高原始分。

同一能力也通过只读 MCP 工具 `hybrid_retrieve_evidence` 暴露。

## 评测

`POST /api/retrieval/evaluate` 接收查询和人工标注的相关 `evidence_id`，计算：

- `Precision@K`：Top K 中相关证据的比例；
- `Recall@K`：全部相关证据被 Top K 找回的比例；
- `MRR`：第一条相关证据排名的倒数；
- `nDCG@K`：考虑排序位置的归一化累积增益；
- `source_coverage`：文档、图谱和案例三路的覆盖比例。

## 当前边界

- 文档路由目前使用本地 hashing embedding，是可重复基线，不代表领域语义模型效果；
- 图谱路由的原始相关度仍需引入路径长度、关系置信度和实体匹配质量；
- 案例路由目前为确定性词项相似度；
- 路由权重尚未通过领域标注集学习，不能宣传为最优权重；
- 仓库内置基准只用于验证实验管道，不足以支撑领域性能结论；
- 后续应在扩充的冻结人工评测集上继续对比交叉编码器和学习排序。
