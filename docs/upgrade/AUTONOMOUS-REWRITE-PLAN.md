# AeroDiagnosis 自顶向下自动重写方案

## 执行原则

从产品用例和不可违反的可靠性约束向下设计，不再以修补旧类或增加装饰性组件推进。新代码
只进入 `src/aerodiagnosis`，旧 `code/python` 保留为迁移期特征测试对象，直到新入口通过契约、
数据迁移和回归门禁后统一退役。

默认由实现代理连续执行、测试和修正文档，不在普通技术选择上暂停。只有真实密钥、外部系统
授权、不可逆数据操作或需求之间存在无法兼容的冲突时才停止。

## 目标架构

```text
HTTP / CLI / MCP
          |
          v
  transport-neutral use cases
          |
          v
 diagnosis workflow + domain tools
      |                 |
      v                 v
 checkpoint port   evidence/graph/case ports
      ^                 ^
      |                 |
 SQLite adapters / optional external adapters
```

## 执行批次与退出标准

### R1 — 应用主干与证据摄取

- 单一组合根；
- CLI/API 共用摄取与检索用例；
- TXT/Markdown/CSV 确定性解析；
- 不可变版本和 active-only 可见性；
- 失败和重复摄取测试。

退出标准：无外部服务的完整门禁通过，CLI 与 API 实机贯通。

### R2 — 可恢复、fail-closed 的诊断工作流

- 诊断命令、证据项、证据主张和报告领域模型；
- 冻结 active version 集合的运行快照；
- 显式 `created → retrieving → assessing → verifying → terminal` 状态；
- 证据不足时改变查询并有限重试；
- 逐主张证据绑定验证，无法验证时拒绝形成结论；
- SQLite checkpoint 保存及相同工作流版本恢复；
- API 诊断与恢复入口。

退出标准：有证据、无证据、纠错、恢复和篡改主张均有自动化测试；生产诊断必须提供真实 LLM/API Key，测试使用受控模型替身。

### R3 — 四类领域工具与真正的条件路由

- 手册混合检索；
- 故障图谱遍历；
- 相似案例；
- 气路参数分析；
- 统一 ToolRequest/ToolResult、deadline、错误码和审计账本。

退出标准：至少三类问题走出不同工具路径，失败工具改变后续动作。

### R4 — 模型适配器与证据约束纠错

- 前端按使用者提交、且不持久化密钥的 OpenAI-compatible 模型适配器；
- Planner、候选诊断和 verifier 的结构化输出；
- verifier 失败反馈必须改变查询、工具或停止原因；
- 无模型配置时不伪造 Agent 诊断，仅保留基础管理能力。

退出标准：禁止默认通过；预算耗尽或模型不可用时返回结构化降级报告。

### R5 — MCP、旧数据迁移与评测

- MCP 与 HTTP 共用相同用例；
- v2 数据导出、哈希校验、导入和抽样回读；
- 冻结数据集、基线、消融和逐样本结果；
- 最后退役旧入口。

退出标准：指标可追溯、迁移可回滚、README 只展示已实测能力。

### R6 — 前端信息架构与知识图谱视觉重排（低优先级）

- 前端直接输入每位使用者自己的模型地址、模型名和 API Key，密钥不落盘；
- 会话列表、诊断时间线、工具轨迹、证据引用与人工复核工作区；
- 知识图谱按症状—部件—故障模式—原因—措施分层，支持路径聚焦、证据抽屉和筛选；
- 在稳定 API 契约上统一视觉语言、响应式布局、空态、错误态与可访问性。
- 深色科技、论文浅色和实验室蓝三种可持久化主题；
- 诊断、知识图谱、案例库和知识管理四个一级模块；
- 本机默认真实模型与每用户自带 API 并存，服务器默认 Key 永不下发前端。

退出标准：不改变后端语义即可替换界面；关键诊断路径有端到端交互测试。

## 当前执行位置

R1–R5 的本机架构闭环已经完成：模型驱动工作流、四类工具、checkpoint、持久会话、MCP、
上传目录迁移和冻结哈希评测均有自动化测试。R6 已完成多主题、四模块工作台、双 provider 模式、
知识上传/版本目录、案例检索、工具轨迹、证据卡片和图谱工作台。论文级金标准与外部 Chroma/Neo4j 迁移需要真实数据和外部系统，
继续作为后续独立里程碑；不会为展示而引入 Kafka、微服务、Kubernetes 或常驻软件。
