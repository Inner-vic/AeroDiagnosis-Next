# 航空发动机气路故障领域数据集构建与标注协议

## 结论先行

要研究文件解析、知识抽取和检索质量，至少需要两类相互隔离的数据：

1. **领域语料库**：系统实际摄取的原始文档及其解析、分块、实体关系和版本记录；
2. **冻结评测集**：不参与调参的查询、相关证据、实体关系金标及标注依据。

缺少专业领域知识不妨碍先搭建管道和完成候选标注，但不能把大模型生成内容直接命名为“金标准”。领域正确性最终需要具备相关背景的标注者或专家抽样复核。

## 语料来源与合规

优先收集公开且许可清晰的材料，例如公开论文及其开放附件、学位论文、公开技术报告、标准中允许使用的内容、设备公开说明、专利和公开故障案例。每份文档必须记录来源 URL、许可或使用依据、获取日期、文件哈希、语言、文档类型与版本。

不要把无法公开的手册、企业运行数据或来源不明的网络文本提交到公共仓库。仓库只保存可再分发样本、元数据清单和获取脚本；受限制原文保存在本地受控目录。

## 三层评测集

### A. 文档解析集

按 PDF、DOCX、HTML、扫描件、表格和纯文本分层抽样。人工标注页面文本、标题层级、段落、表格单元格、图注、公式占位、页码与跨页关系。

建议指标：字符错误率、词错误率、段落边界 F1、标题层级准确率、表格结构 F1、内容保留率和噪声率。扫描件需单独报告 OCR 指标，不能与原生文本 PDF 混算。

### B. 知识抽取集

建立小而明确的领域本体，首版只保留“部件、症状、参数、故障模式、候选原因、检查动作、维修动作”和有限关系。每个实体或关系都必须绑定原文证据跨度与来源版本。

建议指标：实体严格/宽松 Precision、Recall、F1，关系 F1，实体链接准确率，证据跨度准确率，冲突率和无法判定率。先做 100–300 个高质量段落，比自动制造大量低可信三元组更有研究价值。

### C. 检索评测集

从真实使用意图设计查询，覆盖术语查询、症状查询、参数组合、因果追问、排查步骤和同义表达。对每个查询汇集各路 Top N 候选，再由标注者判断“不相关、部分相关、高度相关”，并记录判断依据。

建议指标：Recall@K、Precision@K、MRR、nDCG@K；单路、多路和排序算法必须共享同一查询与知识快照。调参集、验证集和最终测试集按故障主题或文档来源分组切分，避免同一段落改写后跨集合泄漏。

## 无专家条件下的可执行流程

1. 项目成员先阅读少量权威综述和术语表，形成带定义与边界的标注手册；
2. 用规则、现有词表和 LLM 各自产生候选实体、关系、查询和证据池；
3. LLM 只做候选生成与分歧解释，不决定最终标签；
4. 两名标注者独立判断，系统隐藏彼此结果；
5. 一致项进入银标集，分歧项进入仲裁队列；
6. 邀请导师、相关专业研究生或行业人员只复核高价值分歧样本，而非从零标全量数据；
7. 计算 Cohen's Kappa 或 Krippendorff's Alpha，低一致性类别先修改标注手册；
8. 冻结测试集版本和哈希，后续实验不得针对测试集修改规则或权重。

这种方式把稀缺专家时间集中在“定义标准、处理分歧和抽样审计”，同时保留可追溯性。

## 防止数据集自证

- 不用同一个 LLM 同时生成查询、给出相关性标签并评价系统答案；
- 不用待评系统自身的 Top K 作为唯一候选池，应合并各单路召回和人工补充候选；
- 不把同一文档的切片随机拆到训练集与测试集；
- 不在看到最终测试结果后继续调整权重；
- 报告未判定样本、负样本构造方式和标注者一致性，而不只报告最好分数。

## 推荐的最小规模

第一阶段可用 30–50 份许可清晰的文档、150–300 个知识抽取段落和 100–200 个检索查询验证方法。这个规模适合形成可复现的学位论文实验起点，但能否支撑统计结论取决于查询分层、效应大小和标注质量，不能只由样本数量判断。

仓库内的 `evaluation/retrieval/benchmark-v1.json` 是结构示例和流水线冒烟基准。正式数据集应另建版本，记录标注协议、数据卡、变更日志和 SHA-256，并保持测试标签只读。

## 已落地的起步资产

`evaluation/public_aero_corpus_v1/` 已按上述原则落地一份可复现的小规模资产。它包含 10 份公开文档或数据源、17 个原始文件的来源清单与哈希、16 个解析样本、24 条知识抽取候选、30 个文档级检索问题和解析对照基线；来源覆盖 NASA、FAA、NTSB、Federal Register 与 Europe PMC，原始文件横跨 PDF、TXT、HTML、XML、JSON、CSV 六类格式，536 个派生文本块由 `scripts/Build-PublicCorpus.ps1` 下载或生成到 `.runtime/`，不直接进入 Git。

该资产的作用是让解析、抽取、召回和标注流程先运行起来。知识与检索标签仍是 `machine_candidate`，FAA/NTSB 复杂版面、JATS 表格与 SDR 自由文本仍需人工金标，正式论文实验必须先按本协议完成双人独立标注、分歧仲裁和专家抽样复核。许可边界、来源偏差和排除项见 [数据卡](../../evaluation/public_aero_corpus_v1/DATA_CARD.md)。
