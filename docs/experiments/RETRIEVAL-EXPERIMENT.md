# 多路召回对照实验方案

## 研究问题

- **RQ1：** 在相同知识快照与 Top K 下，多路召回相较文档、图谱、案例单路召回，是否提升 Recall@K、MRR 与 nDCG@K？
- **RQ2：** RRF 参数 `k` 对排名质量是否敏感？
- **RQ3：** 路由权重与来源覆盖约束分别带来多少收益或损失？

多路召回是知识问答的底层质量机制，不作为面向使用者的独立功能展示。实验接口和结果文件用于开发验证与学位论文，不进入主操作界面。

## 实验变量与控制

默认实验一次运行 10 个策略：文档单路、图谱单路、案例单路、`RRF(k=10/30/60/90)`、加权 RRF、带来源覆盖约束的生产加权 RRF，以及归一化原始分融合。

所有策略共享：

- 同一冻结查询集及其 SHA-256；
- 同一知识库、图谱和案例快照；
- 同一 `Top K` 和最低相关度；
- 同一候选生成器，仅改变路由选择与排序策略；
- 固定的确定性词法向量基线，不调用 LLM 或外部 API。

这样可以把观察到的差异归因于召回与排序策略，而不是知识变化或模型随机性。

## 指标与统计材料

- `Precision@K`：前 K 条结果中相关条目的比例；
- `Recall@K`：已标注相关条目被召回的比例；
- `MRR`：第一条相关结果位置的倒数；
- `nDCG@K`：考虑相关结果排名位置的归一化折损累计增益；
- `Source Coverage`：文档、图谱、案例三类来源的覆盖率。

运行结果同时保存每个查询的完整指标与命中来源，以及所有策略两两比较的均值差和胜/平/负计数。论文显著性检验应基于 `per_query.csv` 的逐查询结果进行，不能只对汇总均值做检验。

## 复现实验

```powershell
.\scripts\Run-RetrievalExperiment.ps1
```

默认输出到 `.runtime/experiments/retrieval/`：

- `summary.json`：数据集哈希、策略参数与全部结果；
- `strategy_summary.csv`：论文表格所需的策略均值；
- `per_query.csv`：逐查询指标、召回结果和相关性标注；
- `pairwise.csv`：策略两两比较的均值差与胜/平/负。

也可直接运行：

```powershell
.\.runtime\.venv\Scripts\aerodiagnosis-retrieval-experiment.exe `
  .\evaluation\retrieval\benchmark-v1.json `
  .\.runtime\experiments\retrieval
```

## 论文使用边界

仓库自带的 `benchmark-v1` 只用于验证实验管道和形成基线，样本量不足以支撑学术结论。正式论文应扩充查询、采用双人独立标注并报告一致性；训练或调参集与最终测试集必须隔离。只有在冻结测试集上获得的结果才可用于回答 RQ1–RQ3。
